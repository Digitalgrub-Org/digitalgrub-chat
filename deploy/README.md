# Self-hosted Matrix stack

The Compose stack runs Synapse, PostgreSQL, Caddy, daily backups, and an optional
Sygnal push gateway. Only Caddy publishes host ports.

## Configure

1. Point `MATRIX_PUBLIC_HOST` DNS at the server.
2. Copy `.env.example` to `.env`.
3. Replace every example domain, email, and password.
4. Choose `MATRIX_SERVER_NAME` carefully. It becomes the permanent domain in
   every user and room ID and the init service refuses to change it later.
5. Keep registration open only when intended. Production can require Synapse
   registration tokens by setting `SYNAPSE_REGISTRATION_REQUIRES_TOKEN=true`.

## Validate and start

```bash
docker compose --env-file .env config
docker compose --env-file .env pull
docker compose --env-file .env up -d
docker compose --env-file .env ps
curl --fail "https://${MATRIX_PUBLIC_HOST}/health"
```

The `synapse-config` service renders `/data/homeserver.yaml` into the persistent
Synapse volume. Database credentials are therefore absent from Git. Signing and
registration secrets are generated by Synapse at first startup in the same
volume.

Start the optional push process only after replacing `sygnal/sygnal.yaml` with a
deployment-only configuration that references mounted FCM/APNs credentials:

```bash
docker compose --env-file .env --profile push up -d sygnal
```

## Backups

The backup service creates a compressed custom-format dump immediately and then
at `BACKUP_INTERVAL_SECONDS`. Restore tests and off-server copies are required
before production; the named backup volume alone does not protect against loss
of the server itself.

List backup files:

```bash
docker compose --env-file .env exec backup ls -lh /backups
```

The full restore and upgrade runbook is added before the Stage 8 production
gate.
